Section 02

AI Voice Agent Architecture

The voice agent conducts preliminary student counselling through natural conversation, extracts structured information, detects sentiment, and maintains multi-turn memory across sessions.

Operating Modes

Onboarding

KYC collection flow. Agent systematically gathers the 13 required data points through conversational prompts. After the call, transcript is sent to Gemini for structured extraction and auto-saved to the student's MongoDB profile.

Buddy

Persistent memory companion. Remembers everything from past sessions — mood, concerns, goals, preferences. Student can ask questions about universities, visa processes, IELTS preparation, and scholarships.

All fields are extracted via Gemini 2.0 Flash from the conversation transcript. Only explicitly stated facts are captured — no inference or guessing.

Knowledge Base — Two-Layer Architecture

The PS requires "Basic Counselling with Knowledge Base." GradPilot implements this as two complementary layers:

📚

Layer 1: Static Domain KB

The ElevenLabs agent's system prompt contains Fateh Education's domain knowledge — university admission requirements, IELTS/PTE preparation basics, UK/Ireland study costs & scholarships, visa process overview, and application timelines. This handles the 60-70% of FAQ queries.

🧠

Layer 2: Dynamic Per-Student Context

Before every call, /api/voice-agent/memory compiles a real-time context document from: student's 13-field profile, last 15 conversation summaries, all extracted facts, and a completion-aware resume strategy. Injected as dynamic variables into the agent at runtime.

Dynamic Variables Injected Per Session

// Variables sent to ElevenLabs agent before each call { student_name: "Rahul Sharma", student_memory: "## Student Profile\n- Name: Rahul\n- Target: UK\n...", returning_student: "true", resume_mode: "fast-finish", // fresh | resume-focused | fast-finish resume_focus_fields: "budgetRange, englishTestStatus", resume_brief: "Skip intro, confirm details, ask only for budget and test score", skip_opening_sequence: "true", completion_estimate: "84" }

Resume Mode Selection Logic

ModeConditionAgent Behavior
freshFirst conversation, no prior dataNormal opening, collect all fields from scratch
resume-focusedReturning student, 1-3+ missing fieldsBrief acknowledgment, focus on missing fields
fast-finish≤2 missing fields OR completion ≥80%Skip intro entirely, ask only for remaining fields

Sentiment Detection & Memory Extraction

After every voice call ends, a Gemini-powered post-call analysis pipeline runs:

Call ends → ElevenLabs transcript fetched
↓
Gemini 2.0 Flash — Memory Extraction Engine
↓
summary: "Student's needs, preferences, emotional state, decisions made"
extractedFacts: { mood, concerns, goals, targetCountry, budget, ... }
↓
Saved to MongoDB ConversationMemory → available for future sessions

Extraction Prompt: "Analyze this conversation transcript...focusing on the student's needs, preferences, emotional state, and any decisions made. Extract key-value pairs including name, target country, budget, test scores, concerns, preferences, mood, goals, timeline."

This means if a student was anxious about IELTS in Session 1, the voice agent remembers that context in Session 2 without the student repeating it. Counsellors also see the emotional profile in their dashboard.

Live KYC Extraction During Call

While the student is still speaking, a parallel extraction loop runs every 6 seconds:

  • Fetches the latest transcript lines from ElevenLabs
  • Sends new lines to Gemini 2.0 Flash for lightweight extraction
  • Updates the student profile in real-time (without marking KYC complete)
  • Emits counselling-profile:updated events — the LiveKYCChecklist component shows fields turning green as they're captured during the call

Section 03

Lead Qualification & Scoring

Every lead — whether from voice sessions or web research — is scored 0-100 and auto-classified into Hot, Warm, or Cold segments for counsellor prioritization.

Hot Lead   Score ≥ 75

Immediate callback needed. Student has clear goals, budget awareness, and timeline urgency. Campaign leads with email, high-intent keywords (+15 scholarship, +10 UK uni), and direct contact info.

Warm Lead   Score 50–74

Follow-up within 24 hours. Partial profile, showing interest but missing some key data points like budget or test status. LinkedIn profiles with education background.

Cold Lead   Score < 50

Nurture campaign. Early-stage inquiry, browsing communities, no specific plans yet. Reddit users, community pages, and competitor intel entries.

Section 04

Token Optimization Strategy

Four layers of optimization that reduce Gemini API token consumption by approximately 90% on the most frequently hit endpoints.

Layer 1 — Tiered Model Selection

Not every task needs the same model configuration. We route by task complexity:

Model ConfigGemini ModelMax TokensTemperatureUse Case
getReasoningModel()gemini-2.5-pro6,0000.8Strategy, workflow generation
getFlashModel()gemini-2.5-pro8,1920.95Campaign node execution, copy
getImageModel()gemini-2.5-flash-image2,0481.1Visual asset generation
Dashboard Analysisgemini-2.5-pro8,1920.85Student dashboard AI insight
KYC Extractiongemini-2.0-flash——Post-call fact extraction
Sentiment Analysisgemini-2.0-flash——Post-call emotional state

All models use exponential backoff retry: 3 attempts with delays of 1s → 2s → 4s.

Layer 2 — Profile Fingerprint Caching

The most-hit endpoint (/api/dashboard/analyze) uses content-addressed caching:

Student visits dashboard
↓
Hash(name + education + countries + budget + test + ...) → SHA256 fingerprint
↓
MATCH ✓
Return cached analysis
0 tokens • 0ms latency
MISMATCH ✗
Call Gemini → 8,192 tokens
Save new fingerprint + analysis
// Fingerprint includes all profile fields, sorted and lowercased fingerprint = SHA256(JSON.stringify({ name, education, field, institution, gpa, targetCountries: sorted(countries), // sorted for stability course, testStatus, budget, timeline, location })) // Check: if profile unchanged → skip AI call entirely if (cached.profileFingerprint === currentFingerprint) return cached.analysis; // ← zero tokens consumed

Impact: Students view their dashboard ~10x more often than they update their profile. With fingerprint caching, 9 out of 10 dashboard loads cost zero tokens. For 100 students viewing 10x/day: reduced from ~8.2M tokens/day to ~820K tokens/day — a ~90% reduction.

Layer 3 — Rule-Based Fallback (Zero-Token Floor)

If Gemini is unavailable or fails, buildRuleBasedAnalysis() constructs a complete dashboard analysis purely from deterministic code logic — no AI call needed:

  • 7 Journey Steps — Status computed from profile completion (completed / current / locked)
  • 3 Recommendations — Generated from missing fields (language test → urgent, budget → important)
  • AI Insight headline & body — Template-based with student name and target country
  • 2 Counselling Sessions — Priority based on biggest current bottleneck

System never crashes. Token spend has a hard floor of zero as a fallback.

Layer 4 — DAG-Based Context Injection

The campaign workflow engine uses a directed acyclic graph (ReactFlow) to control what context each node receives:

Key principle: Node 3 only receives the output of Node 2 if they're connected by an edge. We never dump the entire workflow history into a single prompt. Each node gets exactly the context it needs via transferLogic on each edge — nothing more.

// compilePrompt() — only includes connected upstream nodes for (edge of incomingEdges) { prompt += `--- ${edge.edgeLabel} ---\n` prompt += `Transfer Logic: ${edge.transferLogic}\n` prompt += `Source Output: ${edge.sourceOutput}\n` } // Only completed upstream nodes are included — no bloated history

Section 06

Observability & Audit Trail

Complete system observability with structured logging across 7 categories and a full security audit trail.

7-Category Agent Logs

Every AI operation writes timestamped JSON records to agent-logs/:

  • agents/ — Agent-level events
  • ai-provider/ — Gemini API calls
  • ai-sdk-executor/ — Prompt compilation
  • api/ — API execution logs
  • errors/ — Error tracking
  • unified-executor/ — Execution engine
  • workflows/web-research-cache/ — Exa.ai research snapshots

Web Research Snapshot Cache

When a research node runs, results are cached to disk:

  • Latest: {nodeId}.json
  • History: {nodeId}-{runId}.json
  • Re-running the same node reads from cache — zero additional API calls
  • Stores: CSV output, leadsWithEmail array, summary metadata

Security Audit Logger

Every API request is audit-logged with:

  • Method, URL, status code, response time
  • User ID, email, session, IP address
  • Request body (sanitized — passwords, tokens, API keys → [REDACTED])
  • Log levels: info warn error critical
  • Categories: auth, campaign, social, workflow, image, api
  • Memory usage tracking per request
Section 07

Authentication & Security

JWT-based authentication with role-based access control, dual auth providers, and comprehensive input sanitization.

Auth Providers

  • Credentials — Email/password signup & signin with bcrypt hashing (min 8 chars)
  • Google OAuth — One-click sign-in, auto-role assignment, existing account linking

RBAC (Two Roles)

  • Student — KYC completion, voice agent, dashboard analysis, onboarding
  • Counsellor — Campaign creation, lead management, Kanban pipeline, voice session review

Session Management

  • Strategy: JWT (stateless, scalable)
  • Max age: 30 days
  • Token payload: { id, role, hasCompletedKYC, email, name, image }
  • Supports session.update() for real-time KYC status sync
